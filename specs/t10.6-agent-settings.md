- **status:** in-progress
- **priority:** P2
- **plan:** `none` — standalone follow-up to Milestone 10. This file is the
  server half of a dual-repo contract; the client half is
  [`TaskTrackerKMP/specs/11.3-agent-settings.md`](../../TaskTrackerKMP/specs/11.3-agent-settings.md).
  ACKed 2026-11-04 with the path map below.

## Scope

The app could dispatch a run, follow it, and cancel it, but it could not answer
"is an agent set up, and is it accepting work?" and an administrator had no way
to stop a machine short of `tt agent disconnect`, which is a permanent
retirement.

This task adds the smallest server-side answer to both:

1. **A reversible stop.** `agent_runners.paused_at` is a date, distinct from
   `revoked_at`: the token stays valid, the machine stays paired, and a start
   restores it.
2. **Two admin routes.** Stop and start over a user JWT, gated by the existing
   admin chain.

What a stop *does* is refuse new claims. The worker runs `tt agent run` on the
customer's machine and this server cannot end that process, so a paused runner is
simply never handed work. Its live run, if any, is flagged `cancel_requested` in
the same transaction — cancel has always been cooperative, observed on the next
heartbeat.

Out of scope, deliberately:

- No process control, no remote shutdown, no hosted relay.
- No change to the run or event key sets, and no new sync entity.
- No "stop snapshots the run in a terminal state" shortcut. A stop asks; the
  worker finishes the run as `cancelled`, which keeps the audit trail and releases
  the one-live-run slot correctly.
- No project-level switch here. `projects.agent_enabled` is already the
  admin-owned, per-project gate; this is fleet availability, not project policy.

## Contract

`agent_runners.paused_at` is nullable epoch milliseconds. `paused_at IS NULL`
means the machine may claim; anything else means it may not.

- [x] A paused runner claims nothing, and a started runner claims the queued run
      again (`TestPausingARunnerStopsClaimsAndFlagsTheLiveRun`).
- [x] Pausing sets `cancel_requested` on the run that machine currently holds,
      in the same transaction, and does not touch a queued run
      (`TestPausingARunnerStopsClaimsAndFlagsTheLiveRun`).
- [x] Stop is reversible and is not revocation: `pausedAt` is set and cleared while
      `revokedAt` stays nil, and the token remains valid.
- [x] A revoked or unknown runner answers `ErrAgentRunnerNotFound`, so a start
      cannot resurrect a retired machine and a stop cannot probe for ids
      (`TestPausingARunnerStopsClaimsAndFlagsTheLiveRun`).
- [x] `POST /v1/agent/runners/{id}/stop` and `/start` are admin-only. A member
      gets `403`; a missing id gets `400`; a missing runner gets `404`
      (`TestTheAdminCanStopAndStartAPairedMachine`).
- [x] The app runner shape gains `pausedAt` and nothing else; the contract test
      pins the closed key set (`TestTheAdminCanStopAndStartAPairedMachine`). This
      is additive: the app that shipped before this change never called
      `/v1/agent/runners`, and the new client declares `pausedAt` with a default.
- [x] No run or event key changed, and nothing entered the sync envelope
      (`cmd/server/contract_test.go` still pins both).

Wire, stop/start response:

```json
{
  "runner": {
    "id": "66666666-6666-6666-6666-666666666666",
    "name": "dev-machine",
    "provider": "openai-compatible",
    "modelLabel": "llama3.1",
    "lastSeenAt": "2026-11-03T12:00:00Z",
    "pausedAt": "2026-11-03T12:05:00Z",
    "createdAt": "2026-11-03T11:00:00Z"
  }
}
```

`start` omits `pausedAt`; a retained key would render the machine as stopped.

- **Gotchas:**
  - Pause is a claim gate, not a kill. Do not try to terminate a worker or mark
    its run terminal from here; the worker owns that transition.
  - The claim query's paused check uses `$1` (the runner id) again, not a new
    placeholder. Placeholders must still ascend in text order for SQLite.
  - `paused_at` belongs in `agentRunnerColumns` *and* the insert, but the read
    projection must keep omitting `token_hash`.
  - Revoked wins over paused: both routes refuse a revoked row with `404` rather
    than clearing its pause.
  - The admin chain is the authorization. The handler deliberately does not
    repeat the role check, the same shape as the admin project handlers.

## Risks / notes

- **Stop latency.** A machine already running a task does not stop on the tap; it
  stops when its next heartbeat sees `cancelRequested`, up to about one beat
  (10 s) plus the model turn in flight. The app's copy says "Stop" and the spec's
  client half records that latency rather than pretending it is instant.
- **Start is not a launch.** Starting a paused machine makes it claim again only
  if `tt agent run` is still running. If the process was closed, the row reads
  running/offline and the operator has to start the process. The client states
  this in the setup sheet.
- **A paused machine still reports.** Heartbeat, events and finish are not gated
  on `paused_at`, deliberately: an in-flight run must be able to finish the
  cancel the stop asked for.
