# T9.7 — `tasktracker://connect` pairing from the CLI

- **status:** done
- **priority:** P0
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §Milestone 9, entry `T9.7` — the
  *what* and rationale live there; this file is the *how*.

## Scope

`cmd/tt` only. No HTTP endpoint, no response shape, and no install-state schema
change: the pairing link is a string the CLI prints after it has verified a
reachable URL, and the client (KMP `6.4`, already merged) owns the grammar.

**The client half is the contract.** `TaskTrackerKMP/specs/6.4-connect-deep-link.md`
defines the link:

```
tasktracker://connect?url=<url.QueryEscape(the whole verified URL)>
```

The client percent-decodes the value exactly once and rejects a malformed
escape, a path after the host, or a missing value. The server therefore escapes
the **whole** URL, including `&`, `#`, `?`, and `%`, and prints nothing when it
has no verified URL to put in it.

**Explicitly deferred:**

- **Recording the verified URL** — T9.8–T9.10. No exposure provider exists yet,
  so `tt install` has no URL to pair with. T9.7 provides the printer; those
  tasks call it with the URL they verified.
- **`tt expose` itself** — T9.8 (LAN), T9.9 (Tailscale), T9.10 (Cloudflare).
  Until then the install output names the command that will produce a URL.
- **A QR code for an unverified address** — a loopback or detected-LAN address
  printed as a scannable code is a phone that cannot connect. The QR is rendered
  only alongside a URL the caller has verified.

## Contract

- [x] `connectLink("https://tasks.example.com")` is exactly
      `tasktracker://connect?url=https%3A%2F%2Ftasks.example.com`.
- [x] The **whole** URL is escaped: a URL containing `&`, `?`, `#`, and its own
      `%2F` arrives at the client unchanged after its single decode
      (`%` → `%25`, `&` → `%26`, `#` → `%23`). Escaping only the path or using
      `url.PathEscape` is a defect.
- [x] Empty input, whitespace, a missing scheme, a non-`http(s)` scheme, a
      missing host, an unparseable URL, and a link too long for the QR's
      capacity return an error and no link. A verified URL is the caller's
      claim; the builder still refuses to emit nonsense or panic.
- [x] `printPairing` with a verified URL prints `Pairing link: <link>` and a
      non-empty terminal QR made of half blocks.
- [x] `printPairing` with no verified URL prints a hint naming
      `tt expose --provider=<the install's provider>` and prints **no**
      `tasktracker://` string and no QR.
- [x] `tt install` (fresh and repair) prints that hint and no pairing link until
      an exposure task supplies a verified URL; the install state schema is
      unchanged.
- [x] The only `go.mod` change is `qrterminal` plus the transitive modules it
      requires (including the `x/sys` bump its `x/term` needs), and
      `go mod tidy` leaves `go.mod`/`go.sum` consistent.

- **Gotchas:**
  - `url.QueryEscape` is the correct encoder for a query **value**; do not
    escape the query key or the literal `tasktracker://connect?url=`.
  - `QueryEscape` turns a space into `+`, which the client's decoder does not
    read as a space. `connectLink` rejects whitespace instead of emitting a
    link that would prefill a different address.
  - The client decodes **once**, so an existing `%2F` in the URL must be
    `%252F` on the wire. A test that decodes twice would pass a broken link.
  - `tt install` has no verified URL in T9.7. Passing `""` is deliberate, not a
    stub; T9.8+ replaces it with the URL it verified, and the hint is the honest
    output until then.
  - `qrterminal.GenerateWithConfig` ignores `qr.Encode`'s error and renders a nil
    code, so an over-capacity link would panic. `connectLink` refuses a link over
    2000 bytes; level M's byte-mode ceiling is 2331.
  - The QR dependency pulls `rsc.io/qr`, `golang.org/x/term`, and an `x/sys`
    bump to v0.29.0. They are indirect; do not downgrade `x/sys` without
    re-running `go mod tidy`.
