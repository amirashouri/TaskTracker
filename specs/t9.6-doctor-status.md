# T9.6 — `tt doctor` and `tt status`

- **status:** done
- **priority:** P0
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §Milestone 9 — Customer install and
  exposure, entry `T9.6` — the *what* and the rationale live there; this file is
  the *how*.

## Scope

Replace the T9.4 stub (`docker compose ps` passed straight through) with the
read-only checks an operator needs. One set of check functions feeds both
commands, so a green `status` and a green `doctor` cannot disagree.

Server-only work: no HTTP endpoint and no wire-format change. The install state
schema is unchanged.

**Explicitly deferred:**

- **Provider-dependent checks** — public DNS, TLS handshake, an external request
  through the provider, and attachment size versus the provider's cap. No
  exposure provider exists until T9.8–T9.10 and `tt expose` records the public
  hostname, so `doctor` reports these as `skip` with the reason rather than
  inventing a green check.
- **Backup creation** — the CLI does not make backups. `status` reports the
  backup age as `skip` and points at `docs/SELF-HOSTING.md` §9. A future backup
  command can turn that into a real age without changing the output format.
- **LAN publishing** — T9.8. The bound-address check pins today's loopback
  publish; T9.8 must extend it when it changes what is published.

## Contract

- [x] `tt status` reports container state, `/readyz`, the bound address, the
      database size, and backup status. It no longer streams raw
      `docker compose ps` output.
- [x] `tt doctor` runs the same status checks, in the same order, then clock skew
      and the provider check. A test asserts the shared prefix is byte-identical
      between the two commands.
- [x] Container check fails when the server (or the Postgres container in
      `postgres` mode) is missing, not running, or unhealthy; a starting
      healthcheck is a warning, not a failure.
- [x] The compose `ps --format json` parser accepts both the JSON-array and the
      one-object-per-line shapes, because the two are emitted by different
      Compose versions.
- [x] The bound address is the one Docker reports
      (`compose port server 8080`), compared with `127.0.0.1:<state port>`. A
      different publish is a failure with a repair instruction, not a silent
      pass.
- [x] Database size is read from inside the container: `stat` for SQLite and
      `pg_database_size` for Postgres. A read failure is a failed check.
- [x] Clock skew compares the local clock with the server's HTTP `Date` header:
      over 2 minutes warns, over 5 minutes fails, a missing header is skipped.
- [x] The provider check reports `skip` with the reason until `tt expose` lands.
      It is never reported as `ok`.
- [x] Backup reports `skip` — no backup is recorded and `tt` does not create
      one — pointing at `docs/SELF-HOSTING.md` §9.
- [x] Exit status is 0 when no check failed, 1 when any check failed. Warnings
      and skips do not fail the command.
- [x] No secret from the install state appears in stdout, stderr, or an error
      detail.
- [x] Every check runs with no Docker daemon and no network through a fake
      environment.

  dependency-ready. T9.7's client half is independent and may land first.
- **Gotchas:**
  - `doctor` must stay `status` plus doctor-only checks, in that order. The
    shared-prefix test is the guarantee that the two commands cannot disagree.
  - The address check pins the loopback publish that T9.3 produced. T9.8 changes
    what is published and must extend this check in the same change; otherwise a
    correct LAN expose reports a failed address until the check is updated.
  - The provider check is a `skip` with the T9.8–T9.10 reason. Do not turn it
    green when a provider is merely configured; it means DNS, TLS, the external
    request, and the attachment cap are unproved.
  - The backup check is a `skip`, not a warning. tt does not create backups;
    reporting an invented age or a permanent yellow line would erode the output.
  - `compose ps --format json` is an array on newer Compose releases and one
    object per line on older ones. Keep both parser paths.
  - The Postgres size read relies on the official image's local-socket trust
    (`psql -U tasktracker` inside the container). It passes no password, so it
    cannot leak one.
  - `status` and `doctor` are read-only. They must not grow a repair path; the
    repair instruction is printed, not executed.

## Risks / notes

- `status` is read-only. It must not call `tt install` steps or write anything;
  a diagnostic command that repairs on its own hides the failure it was meant to
  report.
- The backup line is deliberately a `skip`, not a permanent warning. A check
  that is always yellow trains the operator to ignore the output.
- `compose port` needs the container to exist. A failure there is real: it means
  the install is gone or Docker is unreachable, so the check fails and names
  `tt install` as the repair.
- `compose ps --format json` changed shape across Compose releases. Support both
  shapes now; a single-shape parser works on the author's machine and fails on
  the customer's.
- The clock check trusts the HTTP `Date` header to the second. That is enough for
  JWT and TLS skew, and it costs no extra round trip beyond one `/readyz` GET.
