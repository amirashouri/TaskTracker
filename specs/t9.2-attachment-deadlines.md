## Scope

The global `ReadTimeout` and `WriteTimeout` of 15 s in `cmd/server/main.go` are
correct for the JSON API and bound slowloris. But a 25 MiB upload over a home
uplink cannot complete in 15 s, and the failure only appears when the server
leaves the LAN.

This task adds route-specific deadlines to the two blob routes:
- `POST /v1/projects/{projectId}/work-items/{workItemId}/attachments/{attachmentId}/blob` (Upload)
- `GET  /v1/projects/{projectId}/work-items/{workItemId}/attachments/{attachmentId}/blob` (Download)

using `http.ResponseController` (Go 1.20+) to set per-request read/write
deadlines sized from `ATTACHMENT_MAX_BYTES` and a conservative floor bandwidth.

## Contract

- [ ] Global server timeouts remain 15 s ReadTimeout / 15 s WriteTimeout / 60 s IdleTimeout
- [ ] Attachment blob routes get custom deadlines computed from `ATTACHMENT_MAX_BYTES`
- [ ] Deadline formula: `max(15s, ATTACHMENT_MAX_BYTES / floor_bandwidth)` where floor_bandwidth is a conservative 1 MiB/s (or similar)
- [ ] Uses `http.ResponseController.SetReadDeadline` / `SetWriteDeadline` in the handler
- [ ] JSON API routes still fail after 15 s of inactivity (slowloris protection intact)
- [ ] Test proves: slow upload (>15s) on blob route succeeds; same delay on JSON route fails
- [ ] No wire-format, database schema, or install-state changes

## Risks / notes

- The 1 MiB/s floor is conservative for home uplinks; customers can override via `ATTACHMENT_MAX_BYTES` but not the floor
- If Cloudflare is the provider, `ATTACHMENT_MAX_BYTES` is capped at 100 MiB (T9.10), which at 1 MiB/s = 100 s max deadline
- The test must run both halves: slow blob succeeds, slow JSON fails
