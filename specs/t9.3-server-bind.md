# T9.3 — `SERVER_BIND`, and stop publishing `8080` on every interface

- **status:** done
- **priority:** P0
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §Milestone 9 — Customer install and
  exposure, entry `T9.3` — the *what* and the rationale live there; this file is the *how*.

## Scope

`internal/config` (the new variable), `cmd/server/main.go` (the listen address),
`docker-compose.yml` (the publish), and the two documents that name the variable. No
schema change, no wire-format change, no new dependency.

## Files

Filled from the PLAN entry; confirm at Phase 1 and re-ACK if it moves.

- `internal/config/config.go` — `ServerBind` read from `SERVER_BIND`, default
  `127.0.0.1`; a `validate` rule rejecting anything that is not an IP literal.
- `internal/config/config_test.go` — the default, the `0.0.0.0` opt-in, and a rejected
  hostname.
- `cmd/server/main.go` — `Addr: net.JoinHostPort(cfg.ServerBind, cfg.ServerPort)`.
  `JoinHostPort` rather than string concatenation, so an IPv6 literal is bracketed.
- `docker-compose.yml` — publish `127.0.0.1:${SERVER_PORT:-8080}:8080` on both profiles,
  and an `expose` profile whose server service publishes nothing (the sidecar reaches
  `http://server-pg:8080` over the compose network).
- `.env.example` — the variable, its default, and why loopback is the default.
- `docs/SELF-HOSTING.md` — §4 documents the variable; §8 currently says "bind via
  the proxy and a firewall", which becomes the variable; §10 gains the upgrade note.
- `README.md` — the "Building without Compose" example passes `-p 8080:8080`; it must
  also set `SERVER_BIND=0.0.0.0` or the published port forwards to the container's
  loopback. Added after Phase 1 because the default-loopback change makes the
  existing command false.
- `Makefile` — `down`, `destroy`, and `ps` must include the new `expose` profile,
  or `make down` after `make up PROFILE=expose` leaves the stack running.

## Contract

- [x] With `SERVER_BIND` unset the process listens on loopback only: a connection to the
      host's LAN address is refused while `127.0.0.1` succeeds. The test binds port `0`
      and dials both, so it does not depend on the developer's network.
- [x] `SERVER_BIND=0.0.0.0` makes the LAN address answer. (This is the positive half —
      a test that only pins the default would pass against a hard-coded loopback.)
- [x] A hostname (`localhost`) or an empty value is refused at startup with a message
      naming the variable, not silently resolved.
- [x] `docker compose config` on both profiles shows the host side of the publish as
      `127.0.0.1`, and the `expose` profile shows no `published` key.
- [x] An IPv6 `SERVER_BIND` produces a bracketed `Addr`, so `::1` works rather than
      failing to parse.

## Validation

- Run: `scripts/check.sh` — config and `cmd/server` both have tests; nothing concurrent

- `gofmt -l .` must print nothing.
- The compose assertion is a `docker compose config` check, not a running container: CI

  profile at a time. The Postgres dev publish also moved to loopback.

## Risks / notes

- Easy to get wrong: binding loopback in the container. Inside a container `127.0.0.1` is
  the container's own loopback, so the published port would forward to nothing. The
  compose services must set `SERVER_BIND=0.0.0.0` explicitly; only the *published* side
  moves to loopback. A `curl` from the host is the check that catches this.
- The `expose` profile in this task is a placeholder for T9.9/T9.10 — do not wire a
  provider here, or the task grows into three.
