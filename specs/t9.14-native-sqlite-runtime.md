# T9.14 — Native SQLite runtime (no Docker)

- **status:** in-progress
- **priority:** P1
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §9, entry `T9.14`.

## Scope

`internal/install` and `cmd/tt`, plus the install sections of the docs. No HTTP
contract change, so nothing here crosses into the KMP client.

The goal: a customer who chooses SQLite can install without Docker and get a
working instance that `tt` can still inspect, expose, log and uninstall.

**Fixed by the product constraint:** `tt` never phones home, so it cannot
download a server binary. A native install runs a binary that is already on the
host — `--server-binary`, defaulting to `server` next to the `tt` executable,
then `/opt/tasktracker/server`. Native is Linux + systemd only (the layout
`docs/SELF-HOSTING.md` already documents), SQLite only, provider `lan` only.

## Files

- `internal/install/state.go` — `Runtime`, native state fields, validation,
  empty-runtime normalization for existing `install.json` files.
- `internal/install/native.go` — env-file and systemd-unit rendering, native
  default paths.
- `internal/install/plan.go` — native step kinds and install/logs/uninstall
  plans; `sameInstance` refuses a runtime change.
- `internal/install/runner.go` — native step execution.
- `internal/install/preflight.go` — native preflight: no Docker, root, systemd,
  executable binary.
- `internal/install/checks.go` — `service`, `address`, and `database` checks for
  a native instance.
- `cmd/tt/install.go` — `--runtime`, `--server-binary`, the wizard offer, and
  native output.
- `cmd/tt/expose.go` — `--provider=lan` on a native instance; other providers
  point at the manual steps.
- `cmd/tt/status.go` — print the runtime and the command that supervises it.
- `docs/INSTALL.md`, `docs/SELF-HOSTING.md`, `docs/PLAN.md` — the path, the
  layout, and the task row.

## Contract

- [ ] `tt install --mode sqlite --runtime native --server-binary PATH` installs
      and starts a systemd service, prints the URL and pairing hint, and never
      runs `docker`.
- [ ] The interactive wizard offers "without Docker" after SQLite is chosen; the
      answer is the only thing that turns the runtime on.
- [ ] `--runtime native --mode postgres`, `--provider tailscale|cloudflare`,
      a relative binary path, and a non-root install are refused with the fix.
- [ ] `install.json` without a `runtime` key still loads as a Docker install.
- [ ] A repair reuses the recorded state (secret, paths) and does not create a
      second admin.
- [ ] `tt status`, `tt doctor`, `tt logs`, `tt uninstall` and `tt expose
      --provider=lan` work against a native instance.
- [ ] Uninstall stops and disables the unit, removes the unit and env files, and
      leaves the data directory in place.
- [ ] Docker installs are unchanged: every existing test still passes.

## Validation

- `go test -count=1 ./internal/install ./cmd/tt` — the development loop.
- New pure functions (env/unit rendering, plan, preflight, checks) are tested
  without systemd; runner steps are tested through the injected executor.
- Nothing here needs the race detector: no new concurrency.
- `scripts/check.sh` is the release gate and is not run per task.
- Claims a focused run cannot prove (a real `systemctl` install, unit
  hardening, boot behaviour) are recorded as pending, not claimed.

## Handoff

- **Done:** spec and plan entry; implementation under way.
- **Pending:** the code, tests, and docs below.
- **Next step:** land the state/render/plan layer, then the runner and CLI.
- **Gotchas:** the systemd unit runs as the `tasktracker` system account and the
  data directory is chowned to it, matching `docs/SELF-HOSTING.md` §3. Do not
  point the unit at root to avoid the account setup.

## Risks / notes

- `LoadState` uses `DisallowUnknownFields`, so an older `tt` cannot read a state
  written by this one once the native fields exist. That is a downgrade, not an
  upgrade, and the CLI has no rolling-downgrade contract.
- The native unit's `ExecStart` points at the binary path rather than copying
  it: an upgrade replaces that file, and `tt` must not silently shadow an
  operator-managed build.
