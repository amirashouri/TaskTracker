## Scope

Make a Tailscale install reachable over HTTPS with no project-owned
infrastructure. The command detects the host's Tailscale CLI, requires an
authenticated tailnet with HTTPS certificates, runs Funnel (public) or Serve
(tailnet-only), verifies the `ts.net` URL over HTTPS, and only then prints the
pairing link and QR.

Server-only work: no HTTP endpoint, no wire-format change, and no install-state
schema change. The server keeps its loopback publish; Tailscale reaches it from
`127.0.0.1`, so the compose gains `TRUSTED_PROXIES=127.0.0.1/32` rather than a
public bind.

**File-list drift.** The archive names `cmd/tt/` and `docs/SELF-HOSTING.md`.
Step 5 cannot be satisfied by the CLI alone: the customer compose is generated
from `internal/install/embed/docker-compose.tmpl`, established by T9.4/T9.5 and
already extended by T9.8. This task therefore also changes the embedded template
and its renderer, plus the stale provider text in `internal/install/checks.go`.
None of those is a wire-format or state-schema change.

## Contract

- [ ] `tt expose --provider=tailscale` is accepted. `cloudflare` is still
      refused with a T9.10 pointer, and an unknown provider still gets the
      provider list.
- [ ] The install state's provider must be `tailscale`. A LAN state asked to
      expose as Tailscale is refused before any Tailscale command or compose
      step, and the message names both `tt expose --provider=lan` and the
      reinstall path. A tailscale state asked for the LAN default is refused the
      same way.
- [ ] If `tailscale` is absent from `PATH`, the command prints a platform
      install hint and exits 1 without running `status`, composing, or changing
      the state. It never installs Tailscale or runs `tailscale up` itself.
- [ ] `tailscale status --json` is decoded once. `BackendState` must be
      `Running`; otherwise the command prints `tailscale up` guidance and exits
      1 without composing.
- [ ] HTTPS must be enabled. An empty `CertDomains` list prints the two
      dashboard steps (MagicDNS and HTTPS certificates) and exits 1 without
      composing. The command does not pretend an API token exists.
- [ ] The HTTPS name comes from `Self.DNSName`, trimmed of its trailing dot, or
      the first `CertDomains` entry when `DNSName` is empty. A name with a
      scheme, path, port, or whitespace is never used.
- [ ] The default command is
      `tailscale funnel --bg 443 http://127.0.0.1:<state.ServerPort>`.
      `--tailnet-only` uses
      `tailscale serve --bg 443 http://127.0.0.1:<state.ServerPort>`. The port
      is the install's port, not a hardcoded 8080.
- [ ] The compose written for a tailscale state publishes
      `127.0.0.1:<port>:8080` and contains
      `TRUSTED_PROXIES: "127.0.0.1/32"`. It never publishes `0.0.0.0` and never
      widens `SERVER_BIND` on the host. A LAN render still has no
      `TRUSTED_PROXIES` line.
- [ ] After Funnel/Serve is configured, the command requests
      `https://<name>/readyz` with certificate verification. Only a success
      prints the URL and the `tasktracker://connect` link/QR.
- [ ] A failed HTTPS verification prints the URL, says the Tailscale
      configuration is still active, and names `tailscale funnel reset` or
      `tailscale serve reset`. It does not print a pairing link and does not
      silently reset a configuration the customer may have had.
- [ ] A failing Funnel/Serve command is reported with its own output. Funnel
      failures name the admin-console/ACL step; Serve has no Funnel requirement.
- [ ] A successful command prints the public or tailnet-only URL, states that
      the server stays on loopback behind Tailscale, and prints the reset
      command.
- [ ] `tt install --provider=tailscale` still installs a loopback server and now
      points at `tt expose --provider=tailscale` instead of calling the provider
      unimplemented. Cloudflare still says T9.10.
- [ ] `tt doctor` keeps the provider check as `skip` but gives a Tailscale
      command that can verify the URL, and a T9.10 pointer for Cloudflare.
- [ ] No wire-format, HTTP response, database, or install-state schema change.

## Risks / notes

- Funnel is beta, has an unpublished bandwidth cap, and Tailscale describes the
  Personal plan as non-commercial. The docs must say so; `serve` is the
  tailnet-only alternative.
- Funnel may be disabled by the tailnet's ACLs. The command surfaces the CLI
  error and names the admin-console step; it cannot grant the attribute.
- The install state does not persist the exposed name. `tt doctor` therefore
  cannot re-check the URL without re-running `tt expose`; it stays honest as a
  `skip`.
- The server is in Docker and the host publishes loopback. If a Docker setup
  presents the bridge gateway as the peer rather than `127.0.0.1`, the
  rate-limiter key will still be the gateway; that is a Docker networking
  limitation, not a reason to trust a wider range. The task's documented
  provider contract is the loopback prefix.
