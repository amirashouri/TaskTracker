# T9.1 — Trusted-proxy-aware client address

- **status:** done
- **priority:** P0
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §Milestone 9, entry `T9.1` — the
  *what* and the rationale live there; this file is the *how*. The archived
  T5.6 text is the authoritative task description (see
  [`docs/PLAN-ARCHIVE.md`](../docs/PLAN-ARCHIVE.md) §T5.6).

## Scope

Server-only. The sign-in rate limiter currently keys the per-address budget on
`r.RemoteAddr`. Behind any supported proxy that address is the proxy, so the
per-address limit collapses into one global budget. Read a forwarding header
only when the peer is a configured proxy, and keep today's behaviour when no
proxy is configured.

No HTTP response, wire-format, database, or install/compose change. This is the
prerequisite for the Tailscale and Cloudflare exposure tasks, which set
`TRUSTED_PROXIES` for their sidecars.

## Contract

- [x] `TRUSTED_PROXIES` is a comma-separated list of IPv4/IPv6 CIDRs. Empty
      means trust nothing, which preserves today's `RemoteAddr` behaviour.
- [x] An invalid entry stops startup with an error that names
      `TRUSTED_PROXIES` and the offending value. A bare address is rejected and
      the message suggests the single-host CIDR (`127.0.0.1/32`).
- [x] `0.0.0.0/0` and `::/0` are rejected: trusting every peer makes the header
      forgeable, which is worse than the current global limit.
- [x] Prefixes are parsed once in `config.Load`, masked, and carried as
      `[]netip.Prefix`; no per-request CIDR parsing.
- [x] An untrusted peer's `X-Forwarded-For`/`Forwarded` is ignored and the
      limiter keys on the peer's own address. A test sends different forged
      values from one untrusted peer and still reaches 429 on the third
      attempt.
- [x] For a trusted peer, `X-Forwarded-For` is preferred; `Forwarded` is read
      when X-Forwarded-For is absent. The address list is walked right-to-left,
      returning the first hop that is not in a trusted prefix. If every hop is
      trusted, the leftmost hop is returned.
- [x] A missing, unparsable, or oversized forwarding header falls back to the
      peer address. The whole header is rejected on one bad element; elements
      are not skipped, because skipping shifts the trust boundary.
- [x] Addresses are normalized: IPv4-mapped IPv6 is unmapped, zones are
      dropped, and an optional `:port` or `[...]:port` is accepted.
- [x] The sign-in limiter keys on the resolved address; with `TRUSTED_PROXIES`
      empty, existing per-address and per-account tests are unchanged.
- [x] No wire-format, database, HTTP response, or install-state change.

## Handoff

- **Done:** `TRUSTED_PROXIES` is parsed once at startup as normalized IPv4/IPv6
  CIDRs and passed to the auth handler. The sign-in limiter now keys on the
  forwarded client only when the peer is a configured proxy; it walks
  `X-Forwarded-For` (or `Forwarded`) right-to-left, stops at the first untrusted
  hop, and falls back to the peer for a missing, malformed, or oversized header.
  `.env.example` and `docs/SELF-HOSTING.md` §8 document the variable and the
  trusted-proxy model.
- **Verified:** `scripts/check.sh` and `scripts/check.sh race` green; focused
  `go test ./internal/config ./internal/auth` green; five mutation checks failed
  as named and were reverted; `gofmt -l .` clean; `git diff --check` clean.
- **Pending:** push and MR authorization. No PR is open yet.
- **Next step:** push `feat/t9.1-trusted-proxies`, open the MR, then resume T9.9
  (`tt expose --provider=tailscale`), which can now set `TRUSTED_PROXIES` to the
  loopback prefix for Funnel.
- **Gotchas:**
  - The trusted-prefix decision is about the *peer*, not the forwarded value.
    An untrusted peer's header must never be read.
  - Reject the header as a whole when one hop is unparsable; do not skip the bad
    element and trust the rest.
  - T9.9/T9.10 set `TRUSTED_PROXIES`; a loopback-only proxy is
    `127.0.0.1/32`, not a bare address. The parser rejects a bare address and
    both `/0` prefixes.
  - The oversized-header test must end on a valid address. A trailing comma is
    itself a parse failure, which would hide a missing size cap; the first
    mutation run caught exactly that.
  - Do not add a response field or touch the install state.

## Risks / notes

- The default stays "trust nothing", so an operator who forgets the variable
  gets the current global limit rather than a spoofable header.
- `Forwarded` is parsed only when `X-Forwarded-For` is absent. Supporting both
  simultaneously would need a precedence rule the task does not specify; the
  headers are alternatives, not a combined list.
- Trusting a range wider than the actual proxy re-opens the forgery path. The
  docs say to use the proxy's own address, and `/0` is refused.
