# T9.4 — `tt` CLI: skeleton, state file, and idempotence

- **status:** pending
- **priority:** P0
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §Milestone 9 — Customer install and
  exposure, entry `T9.4` — the *what* and the rationale live there; this file is the *how*.

## Scope

A new `cmd/tt` binary in this module plus the state machine it drives. No server
behaviour change, no wire-format change. The state machine must be testable **without
Docker**, which is what makes this a normal task rather than an integration test.

## Files

To confirm at Phase 1.

- `cmd/tt/main.go` — the composition root: parse the command, load state, dispatch.
  Mirrors `cmd/server/main.go`'s shape (a `switch` on `os.Args[1]`, subcommands in their
  own files) rather than pulling in a CLI framework, unless the prompt/TUI need forces
  one.
- `internal/install/state.go` — the state file: mode, provider, paths, image tag,
  schema version. JSON, `0600`, written atomically (temp file + rename).
- `internal/install/plan.go` — the state machine: `func Next(state State, cmd Command)
  ([]Step, error)`, a pure function. This is the file the tests own.
- `internal/install/runner.go` — the adapter that executes a `Step`; the only place that
  shells out to `docker compose`. Behind an interface so `plan.go`'s tests never touch it.
- `internal/install/embed/` — `go:embed` of `docker-compose.yml`, `deploy/tasktracker.service`,
  and the `Caddyfile`. Embedded rather than read from the working directory: the CLI is
  run from wherever the customer downloaded it.
- `cmd/tt/main_test.go`, `internal/install/plan_test.go`, `internal/install/state_test.go`.
- `Makefile`, `.gitlab-ci.yml` — a release job for the static builds.

## Contract

- [ ] `Next` is pure: given a state and a command it returns the same steps, and its tests
      run with no Docker daemon and no network.
- [ ] **Idempotence:** `install` twice against the same state produces `repair`, never
      `init`. Asserted on the returned step list, not on a rendered message.
- [ ] **The secret is generated once.** A second `install` leaves `JWT_SECRET` byte-for-byte
      unchanged; the test seeds a state with a known secret and asserts it survives.
- [ ] **The image tag is the CLI's own version**, so `tt upgrade` cannot pull a server
      newer than the binary driving it. A test pins that the rendered compose contains the
      tag the build reports.
- [ ] `--dry-run` prints the rendered compose and executes nothing — asserted by the runner
      never being called.
- [ ] A corrupt or partially written state file is reported and refused, not silently
      replaced. (The atomic write means a crash leaves the *old* file, so this is the
      case where the file was hand-edited.)
- [ ] `uninstall` without the instance name typed back exits non-zero and removes nothing.

## Validation

- Run: `scripts/check.sh` and `scripts/check.sh race` if any step is concurrent (it should
  not be; if it is, say why).
- `gofmt -l .` must print nothing.
- No test may require Docker. A `docker`-touching path is exercised by hand once and
  recorded in the MR description; CI has no daemon.

## Handoff

- **Done:** the PLAN entry only. No code.
- **Pending:** the Phase 1 ACK, then `plan.go` and its tests before anything else — the
  state machine is the task; the runner is a thin adapter.
- **Next step:** decide whether a prompt/TUI dependency is acceptable. If yes, it goes in
  `go.mod` and the task says so; if no, the wizard reads from stdin with plain prompts.
  That decision changes the `Files` list, so make it before the ACK.
- **Gotchas:** the CLI and the server must share a module (they do) so the version is one
  value. Do not create a second `go.mod` under `cmd/tt` — that would let the two drift,
  which is the failure this design exists to prevent.

## Risks / notes

- Easy to get wrong: making `install` a script with `if` statements. The state machine is
  what makes "resume after a failure halfway through" testable; a script makes it
  untestable and the resume path is exactly where a non-technical user gets stuck.
- Do not embed the compose file from the working tree at runtime and the embedded copy at
  release time — one source, `go:embed`, always.
