## Contract

- [ ] `docs/INSTALL.md` covers, in order:
  1. What the customer needs: a host, Docker (or T9.12's offer), and which provider wants which account — `lan` wants none.
  2. Install `tt`, then `tt install`, copied from a real terminal on a clean host.
  3. What the QR and the `tasktracker://connect` link do — carry the server URL (T9.7) — and what they do not: carry a password.
  4. The `lan` limitation stated plainly: the Android client blocks cleartext HTTP except `localhost`/`10.0.2.2`, so a phone needs `tailscale` or `cloudflare`.
  5. Day 2: `tt status`, `tt doctor`, `tt upgrade`, backup and restore (the SQLite file, a Postgres dump), and uninstall.
  6. A troubleshooting table where each row is the **actual** message → cause → fix, including `docker: command not found` (→ T9.12) and the Android cleartext refusal.
  7. The constraint, restated once so no customer expects otherwise: the project owns no domain, no relay, and no hosted service, and `tt` never phones home.
- [ ] `README.md` gains a short "Installing for a team" section pointing at `docs/INSTALL.md` — not a second copy.
- [ ] Every command in the doc has been run on a clean host/container; transcript in MR.
- [ ] Documented output matches `tt --help`.
- [ ] Nothing appears in the doc that is not in `cmd/tt`.
